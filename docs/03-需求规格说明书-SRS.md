## 1. 引言

### 1.1 编写目的

明确企业智能知识库系统的功能与非功能需求，作为设计、开发、测试与验收的共同依据，并为后续版本迭代提供需求基线。

### 1.2 项目背景

企业积累了大量规章制度、业务文档与技术资料等非结构化数据。传统文件存储与关键词检索存在**知识分散、查找低效、无法语义理解、知识难以沉淀**的问题；同时，通用大模型存在**数据无法私有化、幻觉严重、无法对接私有资料、安全性差**的缺陷，不能直接用于企业内部答疑。

本项目基于 RAG（检索增强生成）技术，构建私有化企业智能知识库：通过文档解析、向量入库、智能检索与大模型问答，结合权限管控、缓存加速与日志监控，实现企业知识的结构化沉淀与智能化问答。

### 1.3 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| RAG | 检索增强生成，先检索私有文档再让大模型基于检索结果作答 |
| Chunk | 文档切片后的最小检索单元 |
| Embedding | 文本向量化，用于语义相似度计算 |
| BM25 | 经典关键词相关性排序算法 |
| RRF | Reciprocal Rank Fusion，多路检索结果的排名融合算法 |
| Rerank | 对候选片段做二次精排，提升排序准确度 |
| Agent | 可自主调用工具（检索/计算）的大模型执行循环 |
| 熔断 | 达到阈值时中止循环，防止资源耗尽或死循环 |
| perm | 文档权限组标签，用于检索阶段过滤 |

## 2. 总体描述

### 2.1 产品定位

面向企业内部员工的私有化智能问答系统，知识来源限定为企业自有文档，答案必须可溯源至原文。

### 2.2 用户角色

| 角色 | 说明 | 主要诉求 |
| --- | --- | --- |
| 普通员工 | 知识消费者 | 快速、准确拿到答案与出处 |
| 知识库管理员 | 知识维护者 | 便捷入库、覆盖更新、可删除 |
| 系统管理员 | 运维与安全 | 权限隔离、运行监控、故障排查 |
| 集成方（系统） | 内部系统调用者 | 稳定的 API 与清晰的错误码 |

### 2.3 运行环境

| 项 | 要求 |
| --- | --- |
| 服务端 | Linux x86_64；Docker 20.10+ / Docker Compose v2；4C8G 起 |
| 依赖服务 | Qdrant 1.x、PostgreSQL 15 |
| 客户端 | Chrome / Edge 最新版（一期仅桌面端） |
| 网络 | 内网可访问模型服务（或公网白名单出口） |
| 运行语言 | Python 3.9+ |

### 2.4 设计约束

- **DC-1** 私有化部署，业务数据不得离开企业网络。
- **DC-2** 模型能力通过 HTTP 接口调用，需支持替换为内网模型。
- **DC-3** 一期不引入消息队列、搜索引擎等重型中间件。
- **DC-4** 所有配置外置，不得硬编码密钥。

### 2.5 假设与依赖

- 假设企业已有整理好的电子文档（非纯扫描件）。
- 依赖 Embedding / Rerank / LLM 三类外部模型服务的可用性。
- 依赖业务部门指定文档责任人与更新机制。

## 3. 功能需求

> 编号规则：`FR-模块-序号`；优先级：P0 必须 / P1 重要 / P2 期望。

### 3.1 文档入库（FR-ING）

**FR-ING-01 文档上传**　【P0 已实现】
系统应允许管理员通过 Web 页面上传单个文档，支持 `.txt`、`.md`、`.pdf`、`.docx` 四种格式。

**FR-ING-02 格式校验**　【P0 已实现】
系统应在上传时校验扩展名，不在白名单内的文件应被拒绝，并返回明确提示"不支持的文件类型：xxx，仅支持 txt,md,pdf,docx"。

**FR-ING-03 文本解析**　【P0 已实现】
系统应按格式抽取纯文本：PDF 逐页提取、Word 逐段提取、TXT/MD 直接读取。

**FR-ING-04 空内容拦截**　【P0 已实现】
若文件解析后有效文本为空（如纯扫描件、加密文档），系统应终止入库并提示"文档读取成功，但提取文本为空"。

**FR-ING-05 文本切片**　【P0 已实现】
系统应将文本切分为语义完整的片段，默认片长 450~500 字符、重叠 80 字符，切分优先级为 段落 > 换行 > 句号 > 分号 > 空格。

**FR-ING-06 向量化与入库**　【P0 已实现】
系统应对每个片段生成 1024 维向量，并写入向量库，同时保存片段原文、来源文件名、权限组三个字段。

**FR-ING-07 元数据登记**　【P0 已实现】
系统应在关系库登记文档的元数据（文件名、片段数）。**【待补】** 应补充上传人、上传时间、权限组、状态字段。

**FR-ING-08 覆盖更新（幂等）**　【P0 已实现】
同一文件名重复上传时，系统应视为覆盖更新：先删除该文件全部旧片段，再写入新片段，不得产生重复知识。

**FR-ING-09 入库结果反馈**　【P0 已实现】
入库完成应返回"入库成功"与分片数量；失败应返回具体失败原因。

**FR-ING-10 批量入库**　【P2 待开发】系统应支持多文件批量上传与入库进度展示。

### 3.2 知识管理（FR-DOC）

**FR-DOC-01 文档删除**　【P0 部分实现】
系统应支持按文件名删除文档。删除须同时清理向量片段与元数据记录，保证两侧一致。**【现状】** 目前仅清理向量，需补元数据删除。

**FR-DOC-02 文档列表**　【P1 待开发】
系统应以列表展示全部文档：文件名、片段数、权限组、上传人、上传时间、状态，并支持按名称搜索与分页。

**FR-DOC-03 权限组设置**　【P1 待开发】
管理员应能为文档或目录指定权限组（如 `finance`、`hr`、`all`），入库时写入权限字段。

**FR-DOC-04 知识统计**　【P2 待开发】
系统应统计文档总数、片段总数、各权限组文档分布、长期未被召回的文档清单。

### 3.3 智能问答（FR-QA）

**FR-QA-01 单轮问答**　【P0 已实现】
用户输入自然语言问题，系统应返回基于知识库内容的答案。

**FR-QA-02 多轮对话**　【P0 已实现】
同一会话内的追问应结合上文理解（如先问"报销标准"再问"那住宿呢"）；用户点击"新建对话"应清空上下文并生成新会话标识。

**FR-QA-03 输入校验**　【P0 已实现】
系统应拒绝空问题、超过 1000 字符的问题、含非法控制字符的问题，并给出对应提示。

**FR-QA-04 混合检索**　【P0 已实现】
系统应同时执行语义向量召回与关键词召回，并进行融合排序。

**FR-QA-05 精排**　【P0 已实现】
系统应对融合后的候选片段做二次精排，选出最相关的 Top-K（默认 2）片段作为生成上下文。

**FR-QA-06 精排降级**　【P0 已实现】
精排服务异常时，系统应自动降级为原始排序结果，保证问答不中断，并记录告警日志。

**FR-QA-07 答案溯源**　【P0 部分实现】
系统应返回答案所依据的片段原文与来源文件名。**【现状】** 片段已检索到并进入日志，但未通过接口结构化返回给前端，需补充 `sources` 字段。

**FR-QA-08 无答案拒答**　【P0 部分实现】
当知识库无相关内容时，系统应明确回复"未找到相关内容"，不得编造。**【现状】** 依赖提示词约束，需增加相关度阈值判断。

**FR-QA-09 工具调用**　【P0 已实现】
系统应支持大模型自主调用两个工具：知识库检索（`knowledge_search`）与数学计算（`calculate`）。

**FR-QA-10 防死循环熔断**　【P0 已实现】
工具调用轮次不得超过 3 轮；同一工具、同一参数重复调用达到 2 次应触发熔断；熔断后仍应返回可读的兜底回复。

**FR-QA-11 纯检索接口**　【P0 已实现】
系统应提供仅检索接口，返回召回片段而不生成答案，用于调优与二次开发。

**FR-QA-12 流式输出**　【P1 待开发】答案应支持流式返回，首字响应时间不超过 2 秒。

**FR-QA-13 答案反馈**　【P1 待开发】用户应能对答案点赞/点踩并填写原因，用于质量运营。

**FR-QA-14 表格与图片理解**　【P2 待开发】系统应支持表格类问题与扫描件（OCR）内容问答。

### 3.4 权限与安全（FR-SEC）

**FR-SEC-01 检索权限过滤**　【P0 已实现】
检索时必须以用户权限组作为过滤条件下推到向量库，用户的召回结果中不得包含无权限文档的任何片段。

**FR-SEC-02 用户身份绑定**　【P1 待开发】
系统应接入企业统一身份（SSO/账号体系），会话与用户绑定，禁止匿名访问。

**FR-SEC-03 会话隔离**　【P1 待开发】
不同用户的会话上下文不得相互可见。

**FR-SEC-04 审计日志**　【P1 部分实现】
系统应记录"谁、何时、问了什么、命中了哪些文档、返回了什么答案"。**【现状】** 已有日志，缺用户维度。

**FR-SEC-05 敏感内容外发控制**　【P1 待开发】涉密级别内容不得发送至外部模型接口。

### 3.5 性能与运维（FR-OPS）

**FR-OPS-01 缓存加速**　【P1 待开发】
系统应对高频问题与向量化结果做缓存；文档变更时相关缓存应失效。缓存命中响应时间 < 200ms。

**FR-OPS-02 健康检查**　【P1 已实现】
系统应提供健康检查接口，返回服务状态。

**FR-OPS-03 结构化日志**　【P1 部分实现】
系统应输出包含会话标识、耗时、检索结果的日志，便于排障。

**FR-OPS-04 指标看板**　【P1 待开发】
系统应展示问答量、无答案率、平均耗时、熔断次数、热门问题 Top20。

**FR-OPS-05 异常告警**　【P2 待开发】错误率、空召回率、模型服务异常应触发告警。

### 3.6 集成（FR-INT）

**FR-INT-01 REST API**　【P0 已实现】系统应提供标准 REST 接口供内部系统集成。

**FR-INT-02 标准错误码**　【P1 待开发】接口失败应返回标准 HTTP 状态码（4xx/5xx）与统一错误结构，而非恒返回 200。

**FR-INT-03 企业微信/钉钉机器人**　【P2 待开发】系统应支持在 IM 中直接提问。

## 4. 非功能需求

### 4.1 性能需求

| 编号 | 指标 | 要求 |
| --- | --- | --- |
| NFR-P-01 | 完整问答响应时间 | P95 < 5s，P99 < 8s |
| NFR-P-02 | 缓存命中响应时间 | < 200ms |
| NFR-P-03 | 检索耗时（不含模型） | < 100ms |
| NFR-P-04 | 10MB 文档入库耗时 | < 60s |
| NFR-P-05 | 并发能力 | 单实例 20 并发问答无明显劣化 |

### 4.2 可靠性需求

| 编号 | 要求 |
| --- | --- |
| NFR-R-01 | 核心链路可用性 ≥ 99.5% |
| NFR-R-02 | 任一外部模型服务异常时，系统不得返回 500 崩溃页，应给出可读提示 |
| NFR-R-03 | 精排服务异常自动降级，问答成功率不受影响 |
| NFR-R-04 | 入库失败不得在知识库中留下残缺数据 |

### 4.3 安全需求

| 编号 | 要求 |
| --- | --- |
| NFR-S-01 | 权限过滤必须在检索阶段生效，禁止"先召回后过滤" |
| NFR-S-02 | 密钥不得硬编码或提交至代码仓库 |
| NFR-S-03 | 向量库与元数据库默认不对公网暴露 |
| NFR-S-04 | 全链路操作留痕，日志可追溯 |
| NFR-S-05 | 文档内容中的指令性文本不得改变系统行为（防提示词注入） |

### 4.4 可维护性需求

| 编号 | 要求 |
| --- | --- |
| NFR-M-01 | 全部配置通过环境变量注入，支持不改代码切换模型 |
| NFR-M-02 | 配置项集中管理，不得在多处重复定义同名变量 |
| NFR-M-03 | 入库逻辑单一入口，避免多套实现并存 |
| NFR-M-04 | 关键模块（检索、切片、Agent）需有单元测试 |

### 4.5 兼容性与可用性需求

| 编号 | 要求 |
| --- | --- |
| NFR-C-01 | 支持 Chrome/Edge 最新两个大版本 |
| NFR-U-01 | 关键操作（上传、删除、提问）均有明确成功/失败反馈 |
| NFR-U-02 | 错误提示使用业务语言，不暴露堆栈信息给最终用户 |

## 5. 数据需求

### 5.1 数据实体

| 实体 | 关键属性 | 存储位置 |
| --- | --- | --- |
| 文档片段 | 片段ID、原文、向量、来源文件名、权限组 | Qdrant |
| 文档 | 文件名、片段数、（上传人、时间、权限组、状态） | PostgreSQL |
| 会话 | 会话ID、用户ID、多轮历史 | 一期内存 / 目标 Redis |
| 日志 | 时间、会话ID、问题、命中文档、耗时、状态 | 日志文件 |

### 5.2 数据保留

- 会话历史保留 30 天，支持用户主动删除。
- 审计日志保留 ≥ 180 天。
- 文档删除后，向量与元数据同步清除；原始文件按企业档案规定保留。

### 5.3 数据质量要求

- 入库文档需为可解析的电子文本；扫描件需先 OCR。
- 建议要求：单文档 ≥ 200 字、结构清晰、有明确标题与条款编号。

## 6. 接口需求

| 编号 | 接口 | 说明 |
| --- | --- | --- |
| IR-01 | `POST /api/upload` | 上传文档并入库，multipart 表单 |
| IR-02 | `POST /api/delete_doc` | 按文件名删除文档 |

## 7. 验收标准

| 编号 | 关联需求 | 验收方法 | 通过标准 |
| --- | --- | --- | --- |
| AC-01 | FR-ING-01~09 | 上传 4 类文档各 1 份 | 均成功且返回片段数；非法格式被拦截 |
| AC-02 | FR-ING-08 | 同一文件上传两次 | 片段数不翻倍，内容为最新版本 |

| AC-05 | FR-QA-08 | 提问库外内容 10 条 | 100% 明确拒答，无编造 |
| AC-06 | FR-QA-10 | 构造诱导多轮检索场景 | 3 轮内结束，无请求超时 |
| AC-07 | FR-SEC-01 | 低权限账号检索高密文档 | 返回空，无任何片段泄露 |
| AC-08 | NFR-P-01/02 | 压测 100 次问答 | P95 <5s；缓存命中 <200ms |
| AC-09 | NFR-R-02/03 | 断开 Rerank 服务 | 问答仍可用，返回结果正常 |
| AC-10 | FR-DOC-01 | 删除文档后检索 | 向量与元数据均不可见 |
