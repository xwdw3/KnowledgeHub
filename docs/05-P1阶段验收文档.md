### AC-03 提问可召回文档片段并生成答案

**验收方法**：针对刚入库的 TXT 内容提问"员工密码长度要求多少位？多久更换？"，检查召回片段、双路排名、生成答案与引用来源。

**召回实测**：

| 来源文件 | 向量分 | BM25 分 | RRF 分 | 向量排名 | 关键词排名 |
| --- | --- | --- | --- | --- | --- |
| `ace-txt-001.txt` | 0.8470 | 8.5413 | 0.0328 | #1 | #1 |
| `验收TXT.txt` | 0.8470 | 8.5413 | 0.0323 | #2 | #2 |
| `ace-md-001.md` | 0.5917 | 0.7025 | 0.0318 | #3 | #3 |

**生成答案**：

> **结论：** 员工密码长度不得少于十二位，每九十天强制更换一次。[来源1][来源2]
> **依据：** 《信息安全管理办法》第四条：员工密码长度要求不少于十二位。[来源1][来源2] —— 同一办法规定：密码每九十天强制更换一次。

**判定依据**：

- 召回 **3 条片段**，相关度 **0.8454**，远高于拒答阈值 0.25
- 向量召回与 BM25 召回**各自独立排名**（`vec#1` 与 `bm25#1` 同时存在），确认为真双路融合，而非单路按位置打分
- 答案包含全部关键事实（"十二位"、"九十天"），且每句均带 `[来源N]` 标注，可回溯到原文片段
- 耗时：embed 180ms / 向量检索 5ms / BM25 13ms / 端到端 1292ms

**补充验证（拒答能力）**：

提问库外问题时正确拒答，不产生幻觉：

> 知识库中未找到与该问题直接相关的内容（相关度 0.1541，低于阈值 0.25）。最接近的资料是《验收测试制度.md》，但内容不足以回答该问题。

**结论**：✅ 通过

| 第 1 轮 | `knowledge_search` | `{"query":"入职培训 学时","top_k":5}` | 命中 5 条片段 |
| 第 2 轮 | `calculator` | `{"expression":"24*3"}` | `24*3 = 72` |

**生成答案**：

> **结论** 1. 知识库中共有 **6 个文档**。 2. 新员工入职培训**不少于 24 学时**，24 × 3 = **72 学时**。

**判定依据**：

- 单次问答内**串行调用 3 个不同工具**，跨 2 轮完成，证明 Function Calling 循环真实生效
- 3 次调用 `ok=True`，无失败重试
- `break_reason` 为空，正常路径**未误触发熔断**
- 答案正确合并了三类工具结果（文档清单 + 知识检索 + 数值计算）
- 端到端耗时 3529ms

**熔断能力补充验证（单元测试 8/8 通过）**：

### AC-06 环境可复现

**验收方法**：这是最严格的一项——彻底销毁全部容器、数据卷与网络，在**零残留**状态下从零重建，验证是否一次成功且功能完整。

**实测过程**：

1. 执行 `docker compose down -v`，确认容器 0 个、卷 0 个
2. 执行 `docker compose up -d`，耗时 **8.3 秒**
3. 检查自动初始化结果

**重建后实测输出**：

```
NAME              STATUS

rag_p1_postgres   Up (healthy)
rag_p1_qdrant     Up (healthy)

status= ok | vector= qdrant | meta= postgres | points= 0 | docs= 0
```

**PostgreSQL 自动建表结果**（无需手工执行任何 SQL）：

| 表名 | 用途 |
| --- | --- |
| `documents` | 文档元数据与生命周期 |
| `chunks_meta` | 片段元数据 |
| `chat_messages` | 会话消息 |
| `qa_logs` | 问答审计日志 |

**重建后全链路复测**：

- 调用 `/documents/rebuild` 导入示例语料，3 份文档全部成功（各 3 片段）
- 重新执行 `verify_v2.py`，**35/35 通过**
- 空库状态下未出现任何"依赖历史数据才能跑通"的现象

**可复现性保障措施**：

| 措施 | 实现方式 |
| --- | --- |
| 镜像版本固定 | `qdrant/qdrant:v1.12.4`、`postgres:15-alpine` 均锁定具体版本，不用 `latest` |
| 依赖版本收敛 | `qdrant-client>=1.12,<1.13`，与服务端严格对齐，防止自动升级导致行为漂移 |
| 表结构自动初始化 | 应用启动时执行 `CREATE TABLE IF NOT EXISTS`，无需人工建表 |
| 数据与代码分离 | 数据存于 named volume（`rag_p1_qdrant_data`、`rag_p1_pg_data`），镜像不含业务数据 |
| 密钥外置 | 通过 `--env-file` 注入，镜像中无任何明文密钥 |
| 示例语料内置 | 镜像内打包 `data/docs`，`rebuild` 一键恢复演示数据 |

## 四、遗留问题与风险说明

| 编号 | 问题 | 影响 | 处置建议 |
| --- | --- | --- | --- |
| R-01 | Qdrant 与 PostgreSQL 未配置认证（依赖网络隔离） | 低：仅内网可达，宿主机端口未映射 | P2 启用 Qdrant API Key 与 PG 强密码轮换 |

| R-03 | 软删除记录需定期物理回收 | 低：已有 `/documents/purge` 接口 | 建议配置定时任务定期调用 |
| R-04 | Agent 端到端耗时 2~3.5s | 中：受模型服务响应影响 | P2 引入流式输出改善体感 |
| R-05 | 暂无鉴权，任何人可调接口 | 中：不适合直接暴露公网 | P2 首要任务，接入企业 SSO / API Key |

> 以上均为**已知且已评估**的问题，不影响本阶段验收结论；R-05 是进入 P2 的首要动因。
