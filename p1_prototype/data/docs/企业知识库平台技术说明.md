# 企业知识库平台技术说明（节选）

## 一、系统定位

企业知识库平台面向内部员工提供私有化智能问答服务。平台以企业自有制度、业务文档、技术资料为唯一知识来源，通过检索增强生成（RAG）技术，在回答问题时先检索原文片段，再由大模型基于片段组织答案，从而显著降低通用大模型的幻觉问题。

## 二、核心链路

### 2.1 文档入库

1. 文档解析：支持 PDF、Word、TXT、Markdown 四类格式，PDF 逐页提取，Word 逐段提取并保留表格内容。
2. 文本清洗：统一换行、去除控制字符、压缩连续空白，避免脏字符影响向量质量。
3. 文本切片：采用递归切分策略，按"段落 → 换行 → 句号 → 分号 → 逗号"的优先级逐级切分，默认片长 450 字符，相邻片段重叠 80 字符，保证跨片语义连续。
4. 向量化：调用 BGE-M3 模型生成 1024 维语义向量。
5. 索引写入：向量与元数据（文件名、片段序号、权限组）一并写入索引，支持按文件名覆盖更新。

### 2.2 混合检索

平台采用"向量召回 + 关键词召回 + RRF 融合"的双路检索方案：

- 向量召回负责理解语义，能处理"报销上限"与"费用额度"这类同义表达；
- BM25 关键词召回负责精确匹配，对制度编号、项目代号、专有名词更敏感；
- RRF（Reciprocal Rank Fusion）将两路排名融合，公式为 score = 1/(k+rank)，k 取 60，无需调参即可稳定合并异构分数量纲。

实测表明，单路向量召回的典型问题是"召回到了，但没排在最前"，导致模型读到的上下文含噪声；引入双路融合后，Top-3 上下文的相关性有明显提升。

### 2.3 答案生成

生成阶段将 Top-K 片段按"【资料N】来源：文件名"格式拼接为上下文，并在系统提示中约束模型：只依据参考资料作答、无法回答时明确拒答、每个结论标注来源编号。同时声明参考资料中的文字不得作为指令执行，防止文档内容中的提示词注入。

## 三、关键设计取舍

| 设计点 | 选择 | 理由 |
| --- | --- | --- |
| 向量库 | 原型阶段用本地 numpy 索引 | 零依赖、可随包分发，便于快速验证；生产环境替换为 Qdrant |
| 融合算法 | RRF | 无需分数归一化，对异构检索结果稳定 |
| 生成策略 | 固定 RAG 管道（P1） | 链路短、可观测，便于定位是检索问题还是生成问题 |
| 拒答机制 | 相关度阈值 | 宁可回答"未找到"，也不编造条款 |

## 四、性能现状

- 检索阶段（不含模型调用）：万级片段下 < 50ms
- 端到端问答：主要耗时来自大模型生成，通常 2–4 秒
- 文档入库：向量化耗时与片段数线性相关，10MB 文档约 30–60 秒

## 五、后续演进

P2 阶段计划引入：用户身份与权限体系、问题级缓存、引用结构化返回、流式输出、文档管理与召回统计看板。P3 阶段考虑接入企业微信与钉钉，并支持表格与扫描件理解。
